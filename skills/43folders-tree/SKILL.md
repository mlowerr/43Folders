# 43folders-tree

## What a 43Folders tree looks like

```
<parent>/            e.g. 43Folders (name is configurable)
└── 2027/
    ├── 00-Archive/        # "processed / done with" storage spot
    ├── 2027.txt           # year label file (tool-owned header line: "2027")
    └── 01/
        ├── 00-Archive/
        ├── 2027-01.txt
        └── 01/
            ├── 00-Archive/
            └── 2027-01-01.txt
```

Every year, month, and day folder contains exactly one `00-Archive` dir and one
label text file. Month/day names are zero-padded so alphabetical sort is
chronological. The tree is generated by the `43folders` tool (see
43folders-generate for creating/expanding it); this skill covers working with
its content.

## Locating the tree

- If the current directory contains year folders (`YYYY/`) with `00-Archive`
  and label txts, that is the tree (the current dir may itself be the parent,
  or you may be inside the tree).
- Otherwise scan nearby for a parent folder matching the pattern, or ask the
  user for the path. If several trees exist (e.g. Work and Personal), ask which
  one to use for each task.
- When running the generator later, the parent is `--root/<name>`; keep that
  pair consistent.

## Content protocol (follow unless the user says otherwise)

These conventions keep the tree consistent, sortable, and non-destructive
across any AI harness. Follow them for every task below.

### Label files (`YYYY.txt`, `YYYY-MM.txt`, `YYYY-MM-DD.txt`)

- The **first line is the tool-owned header** (the label itself). Never remove
  or reword it. If it is missing, restore it by prepending the label line.
- User/agent content goes **after** the header: a blank line, then bullet
  items (`- <text>`). These files are the capture surface — use them for notes,
  ideas, logs, and filing small items.
- Example append:
  ```
  2027-01-01
  (blank line)
  - Drank coffee with Sam
  - Idea: holiday card design
  ```

### Review and to-do files

Period summaries live in one file per period: `<label>-review.txt` (e.g.
`2027-01-05-review.txt`, `2027-01-review.txt`, `2027-review.txt`), placed in:

| Period | Filename | Folder |
| --- | --- | --- |
| Day | `YYYY-MM-DD-review.txt` | the day folder |
| Week (Mon-Sun) | `YYYY-Www-review.txt` (ISO week, e.g. `2027-W03-review.txt`) | the year folder |
| Month | `YYYY-MM-review.txt` | the month folder |
| Year | `YYYY-review.txt` | the year folder |

Structure of a review file:

```
2027-01-05-review
(blank line)
## Review
<summary of the period: what happened, highlights, patterns>
## Todos
- [ ] <action item 1>
- [ ] <action item 2>
```

To-dos are plain checkbox items (`- [ ]`); mark progress with `- [x]`. A review
with no meaningful highlights still gets a short `## Review` paragraph. Write
day reviews into the day folder, week/month/year reviews into their periods as
above.

### New files

- UTF-8, LF line endings.
- Filenames: ASCII only; safe on every OS — no `<>:"/\|?*`, control chars,
  leading/trailing whitespace, trailing dots, or Windows device names
  (CON/PRN/AUX/NUL/COM1-9/LPT1-9).
- Follow `<period>-<topic>.txt` naming so files sort chronologically beside
  their label file (e.g. archive a receipt as `2027-03-05-rent-receipt.txt` in
  the day folder).

### Safety rules (never break)

1. **Never delete anything** — not files, not folders, not `00-Archive`
   contents.
2. **Never overwrite content you did not create in this task** — append, use
   new files, or edit only the exact lines the user pointed at.
3. Do not touch unrelated files while adding to a period.
4. Prefer **copy over move** when a user wants something "filed" into an
   archive; move (delete of the source) only with explicit user confirmation.

## Common tasks

### Filing an item into a date (past or future)

1. Resolve the target date (see Date math below).
2. Small item (thought, link, reminder) -> append a bullet to that day's label
   file: `- <item>`.
3. Larger item (document, receipt, notes) -> write a new file
   `YYYY-MM-DD-<topic>.txt` in that day's folder; if the user wants it "stored
   away", write it into that day's `00-Archive/` instead (copy, don't move).
4. If the target day folder does not exist, either compute with a different
   date or expand the tree (see 43folders-generate); tell the user which you did.

### "My {day/week/month/year} in review" + to-dos

1. Gather the period's content: label files of every date in the period (and
   their `-review.txt` files; include `00-Archive` contents only if the user
   asks for archived material too).
2. Summarize: what happened, highlights, loose ends. Be concrete — reference
   actual entries and dates.
3. Write the review file at the protocol location with `## Review` and
   `## Todos` sections (see table above).
4. Review content is grounded in what you read; don't invent events. If a
   period is empty, say so in the review.

### Adding/editing a note for a date

- New note -> append a bullet to that date's label file (or a new
  `YYYY-MM-DD-<topic>.txt` for substantial content).
- Editing -> edit only the targeted lines, preserving everything else and the
  header line.

### Reading / summarizing a period

- Collect the label files for the period's dates, sort by name (chronological
  by construction), and summarize. Mention which days had no entries.
- Archive contents are excluded unless requested.

### Checking gaps or "do I have all of 2027?"

- Compare the year folder's day folders against the calendar, or re-run the
  generator with `--dry-run --quiet` (see 43folders-generate) and diff the
  year totals; add missing folders with a real run (safe, idempotent).

### Searching the tree

- Run content searches across the tree root (e.g. ripgrep) with patterns for
  the topic; include `00-Archive` only when the user asks for archived hits.
- "When did I do X?" -> search, then report matching dates with one-line
  context each, citing the file path.

## Date math

- Path for date `YYYY-MM-DD` is `<tree>/<YYYY>/<MM>/<DD>/` (zero-padded)
  with label file `<YYYY-MM-DD>.txt`.
- Validate real dates (leap years: Feb 29 valid only in leap years).
- "Today"/"tomorrow"/"next Monday" -> use the machine's local date; if the time
  zone could matter, confirm the date with the user.
- Reachable via standard library only; no external date packages needed.
